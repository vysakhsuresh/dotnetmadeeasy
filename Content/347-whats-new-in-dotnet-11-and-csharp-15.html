What's New in .NET 11 and C# 15: A Beginner's Guide

All levelsLesson 302 of 325·Production .NET·18 min read·Updated 11 Nov 2026

Every November, .NET gets a new version and C# gets new syntax. This is your plain-English map of what arrived with .NET 11 and C# 15, and what it means for the code you write.

If you've followed this course from the start, you've been writing C# 14 on .NET 10. On 10 November 2026, Microsoft released .NET 11, and with it C# 15. Release notes for a new version are long and full of words like intrinsics and devirtualization, which can make it feel as if you have to start learning all over again.

You don't. Most of a new release happens under the hood: your existing code simply runs a little faster. The parts you do need to learn are small, focused additions, and this Part teaches each one slowly, with examples, in the lessons that follow.

In this lesson, you'll learn what .NET 11 and C# 15 are, how long .NET 11 is supported and how that compares with .NET 10, which new features matter for everyday code, and where in this Part each one is explained step by step.

What Is It?

The Simple Explanation

.NET 11 is the newest version of the .NET platform: the runtime that runs your program, the libraries you call (like List<T> and HttpClient), and the dotnet command-line tools. C# 15 is the newest version of the C# language: the words and symbols you're allowed to write. The two arrive together. When you install the .NET 11 SDK, you get the C# 15 compiler inside it.

Think of .NET as the kitchen and C# as the recipe language. .NET 11 is a renovated kitchen with faster appliances. C# 15 adds a few new words to the recipe language so that some recipes become shorter and safer to write.

The Technical Definition

.NET 11.0.0 was released on 10 November 2026 together with SDK 11.0.100. It is a Standard Term Support (STS) release, supported with fixes and security patches until 14 November 2028. Projects opt in by targeting the framework moniker net11.0. C# 15 is the default language version for projects that target net11.0, so its features work without any extra setting, except the memory-safety work, which is still a preview. You can use the .NET 11 SDK from the command line or with Visual Studio 2026.

.NET 10 (LTS)

  • Released November 2025
  • Long Term Support: supported until 14 November 2028
  • Comes with C# 14
  • Target framework: net10.0
  • A great choice when you want the longest-lived stable base

.NET 11 (STS)

  • Released 10 November 2026
  • Standard Term Support: also supported until 14 November 2028
  • Comes with C# 15
  • Target framework: net11.0
  • A great choice when you want the newest features today

Notice something surprising in that table: .NET 10 and .NET 11 stop being supported on the same day. .NET 10 gets three years of support because it's an LTS release; .NET 11 gets two years because it's an STS release, but it started a year later. Meanwhile, .NET 8 and .NET 9 both reached end of support on 10 November 2026, the same day .NET 11 shipped. If you have an app on either of those, it's time to move.

Why Does It Exist?

The Problem — Software Never Stands Still

Hardware gets faster, cloud platforms change, and developers keep running into the same small annoyances in the language. If .NET only changed every five years, every release would be a giant, risky jump. Teams would put off upgrading, and security fixes would be harder to deliver.

The Solution — A Predictable Yearly Release

Microsoft ships a new major version of .NET every November, alongside a new version of C#. Even-numbered versions (.NET 8, .NET 10) are LTS, supported for three years. Odd-numbered versions (.NET 9, .NET 11) are STS, supported for two years. Because the schedule is predictable, teams can plan: some upgrade every year to get new features, others jump from one LTS release to the next.

How It Works

FROM "NEW VERSION RELEASED" TO "NEW FEATURES WORK IN MY PROJECT"
1. INSTALL THE .NET 11 SDK
  • Download it from the official .NET download page, then check it in a terminal with dotnet --list-sdks. You should see a line starting with 11.0.
  • Installing a new SDK does not remove older ones. .NET 10 projects keep working.
▼
2. TARGET net11.0 IN THE PROJECT FILE
<TargetFramework>net11.0</TargetFramework>
▼
3. C# 15 SWITCHES ON AUTOMATICALLY
  • The compiler picks the default C# version from the target framework. net11.0 means C# 15. You don't need a LangVersion setting.
▼
4. BUILD AND RUN AS USUAL
  • dotnet build and dotnet run work exactly as before. Your old code compiles unchanged, and the new syntax is now available.

The C# 15 Features on One Page

Here is every C# 15 feature with a one-line taste. Each of the first five has its own full lesson in this Part, so don't worry if a line looks unfamiliar right now.

1. Union types — "this value is one of these types"

public union Pet(Cat, Dog, Bird); // a Pet holds exactly one Cat, Dog or Bird

A union lets one variable hold one of a fixed list of types, and the compiler checks that your switch handles every one. See lesson 348.

2. Closed hierarchies — "only these subclasses, ever"

public closed record class JobStatus; // only this project may add subclasses public record class Queued : JobStatus; public record class Done : JobStatus;

The closed keyword fixes the list of direct subclasses, so a switch over them needs no default case. See lesson 349.

3. Collection expression arguments — settings inside the brackets

HashSet<string> tags = [with(StringComparer.OrdinalIgnoreCase), "C#", "c#"]; // 1 item

A with(...) element at the start of [...] passes arguments such as a capacity or a comparer to the collection. See lesson 350.

4. Extension indexers — square brackets on types you don't own

extension(IEnumerable<int> sequence) { public int this[int index] => sequence.ElementAt(index); }

C# 14's extension blocks can now declare indexers too. See lesson 351.

5. Labeled break and continue — jump out of nested loops cleanly

outer: for (int row = 0; row < 3; row++) { for (int col = 0; col < 3; col++) { if (col == row) continue outer; // skip straight to the next row } }

No more Boolean flags or goto to escape two loops at once. See lesson 352.

6. Two smaller additions

  • Non-virtual static interface members on older runtimes. An interface can now carry a plain static helper method, such as IMeasurement.ToMeters(250), even when a library targets an older runtime. This mostly matters to library authors.
  • Memory safety (preview). The first step of a multi-year redesign of unsafe code. It only affects code that uses pointers, and it needs <LangVersion>preview</LangVersion>, so most developers can safely ignore it for now.

What's New in the Platform

  • Runtime async (preview). The runtime itself can now run async methods instead of relying only on compiler-generated code, giving shorter stack traces and less overhead. Your code doesn't change. See lesson 353.
  • Faster code for free. JIT improvements remove more bounds checks and devirtualize more calls. .NET 11 also now requires a more modern CPU (x86-64-v2 on Intel and AMD), which every chip supported by Windows 11 already meets.
  • New library APIs. LINQ gains FullJoin and joins that return tuples, Process.RunAndCaptureTextAsync runs a command and captures its output in one call, EqualityComparer<T>.Create builds a comparer from one lambda, and System.Text.Json can write JSON Lines. See lesson 354.
  • SDK and tools. dotnet run -e NAME=value passes environment variables, file-based apps can be split across files with #:include, and dotnet new mcpserver creates a server that AI assistants can call.
  • ASP.NET Core 11 and EF Core 11. Async validation, OpenAPI 3.2 by default, Zstandard compression, union types in APIs, and EF Core translating FullJoin to SQL FULL JOIN. See lesson 355.

When you're ready to move a real project across, lesson 356 walks through the upgrade step by step.

Simple Example

Here is a complete little program that uses two C# 15 features. Put it in Program.cs in a project that targets net11.0, then run dotnet run.

// Program.cs: a first taste of C# 15 (needs the .NET 11 SDK) HashSet<string> seen = [with(StringComparer.OrdinalIgnoreCase), "Apple", "APPLE", "Banana"]; Console.WriteLine(seen.Count); // 2: "Apple" and "APPLE" count as the same word Shape shape = new Circle(2.0); Console.WriteLine(Area(shape)); // 12.566370614359172 static double Area(Shape shape) => shape switch { Circle c => Math.PI * c.Radius * c.Radius, Square s => s.Side * s.Side, }; public record class Circle(double Radius); public record class Square(double Side); public union Shape(Circle, Square);

Code → Meaning → Result: The first two lines create a set that ignores upper and lower case, so the two spellings of "Apple" collapse into one entry. The rest declares a Shape that is either a Circle or a Square. The switch has no default arm, and it doesn't need one: the compiler knows those are the only two possibilities.

Real-World Example

Imagine you lead a small team with three apps: an internal tool on .NET 8, a customer website on .NET 9, and a brand-new API you're about to start. Here's how the release affects each one:

  • The .NET 8 tool is now out of support. It should move to .NET 10 (LTS) or .NET 11. Both are supported until November 2028, so pick whichever your team is more comfortable with.
  • The .NET 9 website is also out of support. Moving to .NET 11 is usually a small step: change net9.0 to net11.0, update NuGet packages, run the tests.
  • The new API can start directly on .NET 11 and use C# 15 from day one, or start on .NET 10 if your company prefers LTS releases only. Either way, you're covered until November 2028.

Analogy

A Yearly Phone Update

Your phone gets a big software update once a year. Most of it you never notice: things open a bit faster and the battery lasts longer. A few new buttons appear, and you learn them when you need them.

Some phone models get updates for longer than others. .NET works the same way: every version gets the yearly speed-ups, LTS versions are the "long support" models, and STS versions are the "newest features" models. Neither is a beta; both are finished products.

Under the Hood

  • Runtime version and SDK version are different numbers. The runtime is 11.0.0; the SDK, which contains the compiler and the dotnet tool, is 11.0.100. Monthly patches bump them to 11.0.1 and 11.0.101, and so on.
  • The C# version follows the target framework, not the SDK. With the .NET 11 SDK installed, a project that targets net10.0 still compiles as C# 14 by default; only net11.0 projects get C# 15 automatically.
  • Many SDKs can live side by side. Installing .NET 11 doesn't remove .NET 10. A global.json file can pin a project to a specific SDK when you need that.

Common Confusion

1. "STS means beta or unstable" — no, it's only about how long support lasts

STS releases go through the same testing as LTS releases and are fully supported in production. The only difference is the length of the support window: two years instead of three.

2. "Installing the .NET 11 SDK upgrades all my projects" — no, each project chooses its target

A project keeps targeting whatever its <TargetFramework> says. Nothing changes until you edit that line to net11.0.

3. "I have to rewrite my code for the new version" — no, old code keeps working

C# almost never removes features. The new syntax is optional, and you can adopt it one file at a time, or not at all.

Common Mistakes

Mistake 1 — Turning on preview features in production code

The mistake: Enabling runtime async for your own code, or <LangVersion>preview</LangVersion> for memory safety, in an app that serves real customers, because they sounded exciting in the release notes.

The fix: Use preview features in experiments and side projects first. The rest of C# 15 and .NET 11 is fully released and safe to use.

Mistake 2 — Forgetting that .NET 8 and .NET 9 are now out of support

The mistake: Leaving an app on .NET 8 or .NET 9 after 10 November 2026. It keeps running, but it no longer receives security fixes.

The fix: Plan a move to .NET 10 or .NET 11. Lesson 356 shows the steps.

When Should I Use It?

  • New projects: start on .NET 11 if you want C# 15 today, or on .NET 10 if your organisation only uses LTS releases. Both are supported until November 2028.
  • Apps on .NET 8 or .NET 9: move now, to either version.
  • Apps on .NET 10: no rush. Upgrade when you want a specific new feature.
  • Learning: use .NET 11. This course's examples now target it.

Mental Model

.NET 11 = the platform (runtime, libraries, tools). C# 15 = the language. They ship together every November.
LTS (even numbers) = 3 years of support. STS (odd numbers) = 2 years. Both are production-ready.
net11.0 in the project file turns on C# 15 automatically.

Remember: .NET 11 makes your existing code faster for free; C# 15 adds a handful of new words you can learn one at a time.

Key Takeaway

  • .NET 11 shipped on 10 November 2026 with C# 15. It's an STS release supported until 14 November 2028, the same end date as .NET 10 LTS.
  • .NET 8 and .NET 9 reached end of support the day .NET 11 shipped.
  • C# 15 adds union types, closed hierarchies, collection expression arguments, extension indexers, and labeled break and continue.
  • The platform adds runtime async (preview), faster code, and new library, SDK, ASP.NET Core and EF Core features.
  • Upgrading usually means installing the SDK, changing net10.0 to net11.0, and running your tests.

Check Your Understanding

Three quick questions to check the big picture landed.

1. How long is .NET 11 supported, and how does that compare with .NET 10?

  • A) Until November 2027, a year less than .NET 10
  • B) Until 14 November 2028, the same end date as .NET 10
  • C) Forever, because it's the newest version
  • D) Until 2029, a year longer than .NET 10
Show answer

Correct: B

Why B is correct: .NET 11 is an STS release supported until 14 November 2028. .NET 10 is an LTS release that started a year earlier, so its three years also end on 14 November 2028.

Why A is incorrect: STS releases now get two years of support, so a November 2026 release is supported until November 2028.

Why C is incorrect: No .NET version is supported forever. Every release has a fixed end-of-support date.

Why D is incorrect: Neither version is supported into 2029; both end in November 2028.

Reinforcement: Even = LTS (3 years), odd = STS (2 years), and this time both windows end on the same day.

2. You install the .NET 11 SDK. Which project automatically compiles with C# 15?

  • A) Every project on the machine
  • B) Only projects whose <TargetFramework> is net10.0
  • C) Only projects whose <TargetFramework> is net11.0
  • D) None, because C# 15 always needs <LangVersion>preview</LangVersion>
Show answer

Correct: C

Why C is correct: The default C# version comes from the target framework. net11.0 projects get C# 15; a net10.0 project stays on C# 14 by default.

Why A is incorrect: Installing an SDK doesn't change any project's settings. Each project's target framework decides its default language version.

Why B is incorrect: net10.0 projects default to C# 14, the language version that shipped with .NET 10.

Why D is incorrect: Apart from the memory-safety preview, C# 15 features are fully released and need no preview setting.

Reinforcement: Change net10.0 to net11.0 and C# 15 switches on by itself.

3. What does STS mean for an app you run in production?

  • A) It's a beta that shouldn't be used for real customers
  • B) It's a fully supported release with a shorter support window than LTS
  • C) It only runs on Windows
  • D) It can't be used with Visual Studio
Show answer

Correct: B

Why B is correct: STS (Standard Term Support) releases are finished, production-ready releases. They're supported for two years instead of three.

Why A is incorrect: STS isn't a preview or beta. Preview builds come out months before release day.

Why C is incorrect: .NET 11 runs on Windows, macOS and Linux, just like .NET 10.

Why D is incorrect: You can use the .NET 11 SDK with Visual Studio 2026, or from the command line with any editor.

Reinforcement: STS vs LTS is only about how long support lasts, not about quality.
