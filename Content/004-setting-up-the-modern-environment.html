Your gateway to C# development — getting started in under 10 minutes.

Imagine you've decided to learn a new language — say, French. You have the motivation, the books, and the desire. But without a way to practice speaking, listening, and writing, you'll never truly learn.

The same applies to C# and .NET. You can read about variables, loops, and classes all day, but until you have a working development environment, you can't write, run, or test any code. Your environment is your practice ground — the place where ideas become working software.

In this lesson, we'll walk through setting up everything you need to start writing and running C# code. By the end, you'll have a fully functional development environment and will have written and executed your very first C# program.

What Is It?

The Simple Explanation

Setting up your development environment means installing the tools you need to write, build, and run C# code on your computer.

The Technical Definition

A development environment consists of:

  1. The .NET SDK (Software Development Kit) — The runtime, compiler, and command-line tools needed to build and run .NET applications.
  2. A Code Editor or IDE (Integrated Development Environment) — The place where you write your code.
  3. The dotnet CLI — A command-line interface that lets you create, build, run, and publish applications.

Why Does It Exist?

The Problem

When you start learning to code, one of the biggest hurdles is just getting started. You might have a great idea or want to follow along with a tutorial, but:

  • You don't know what software to install.
  • Different tutorials recommend different tools.
  • You're worried about breaking your computer.
  • The setup process feels overwhelming.

Many aspiring developers give up before writing a single line of code because the setup process seems too complicated.

The Need

You need a simple, reliable way to get from "I want to code" to "I'm writing and running code" with minimal friction.

The Solution

Microsoft created the .NET SDK as a unified package that includes everything you need to build .NET applications. Combined with a free, lightweight editor like Visual Studio Code, you can be up and running in under 10 minutes.

🎯 The Beautiful Part

You don't need expensive software or complex configurations. The .NET SDK and VS Code are both completely free and work on Windows, macOS, and Linux.

How It Works

Let's break down the setup process into clear, actionable steps:

Step 1 — Install the .NET SDK

The .NET SDK is the foundation of everything. It includes:

  • The .NET Runtime — Executes your C# code.
  • The C# Compiler (csc) — Translates your C# code into Intermediate Language (IL).
  • The dotnet CLI — A command-line tool for creating, building, and running projects.
  • The Base Class Library (BCL) — Thousands of pre-built classes and methods.

Where to get it: Download from dotnet.microsoft.com/download

How to install:

  • Windows: Run the installer (.exe) and follow the prompts.
  • macOS: Run the installer (.pkg) and follow the prompts.
  • Linux: Follow the package manager instructions for your distribution.
💡 Pro tip: The installer handles everything automatically. Just click "Next" a few times!

Step 2 — Verify the Installation

Open your terminal or command prompt and run:

dotnet --version
dotnet --info

You should see output showing the version number and detailed information about your .NET installation.

💻 Why do we need the SDK?

The SDK gives you the dotnet command-line tool, which lets you create, build, run, and publish applications without opening an IDE. This is essential for automation, CI/CD pipelines, and rapid development.

Step 3 — Choose Your Editor / IDE

Tool Platform Best For
Visual StudioWindowsLarge enterprise solutions
VS Code ✅Windows, macOS, LinuxBeginners, cross-platform
RiderWindows, macOS, LinuxPowerful refactoring (paid)
💡 Pro tip: If you're just starting out, VS Code is the easiest way to get going. It's free, fast, and works on any machine.

Step 4 — Create Your First Project

Open your terminal and run:

dotnet new console -n MyFirstApp
cd MyFirstApp

This creates a new console application in a folder called "MyFirstApp".

What the command does:

  • dotnet new console — Creates a new console application template.
  • -n MyFirstApp — Names the project "MyFirstApp".
  • cd MyFirstApp — Moves into the project folder.

Step 5 — Run Your Application

dotnet run

You should see:

Hello, World!

🎉 Congratulations! You've just written and run your first C# application.

Under the Hood

When you run dotnet new console -n MyFirstApp, here's what happens internally:

WHAT HAPPENS WHEN YOU CREATE A PROJECT
Your Command: dotnet new console -n MyFirstApp
↓
1. The dotnet CLI reads the command and parameters
2. It looks for the "console" template
3. It creates a folder called "MyFirstApp"
4. It copies template files into the folder:
  • Program.cs (with the basic Hello World code)
  • MyFirstApp.csproj (project configuration)
5. It restores dependencies (nuget packages)

Project Structure Explained

MyFirstApp/
├── Program.cs          ← Your C# code (the main program)
├── MyFirstApp.csproj   ← Project file (settings, dependencies)
├── obj/                ← Temporary build files (don't touch)
│   └── ...
└── bin/                ← Build output (don't touch)
    └── Debug/
        └── net8.0/     ← Compiled application
            └── MyFirstApp.dll

Common Mistakes

Mistake 1 — Forgetting to Add the C# Extension in VS Code

❌ Wrong: Installing VS Code and trying to write C# without the C# extension.

✅ Correct: Install the C# extension from the marketplace (by Microsoft). It provides IntelliSense, debugging, and project management.

Mistake 2 — Opening the Wrong Folder

❌ Wrong: Opening the parent folder (e.g., Documents) instead of the project folder.

✅ Correct: Open the folder that contains the .csproj file.

cd MyFirstApp
code .          ← Opens the current folder

Mistake 3 — Forgetting to Restore Packages

❌ Wrong: Running dotnet run and seeing errors about missing packages.

✅ Correct: Use dotnet restore first, or just dotnet run (which restores automatically).

dotnet restore   ← Restores all dependencies

Mistake 4 — Not Understanding the Difference Between Debug and Release

❌ Wrong: Building and deploying the debug build to production.

✅ Correct: Build for release when deploying:

dotnet build -c Release

When Should I Use It?

You should set up a .NET development environment when:

  • You want to learn C# and .NET.
  • You need to build a new C# application.
  • You're joining a .NET project at work or in open source.
  • You want to experiment with new .NET features.

When it might be overkill:

  • You just need to run an existing .NET application — you only need the runtime.
  • You're doing quick scripting — consider Python or PowerShell.
  • You're on a system with limited storage — VS Code is a better fit than full Visual Studio.

Key Takeaway

  1. The .NET SDK includes the runtime, compiler, and command-line tools — everything you need to build .NET applications.
  2. Visual Studio Code (with the C# extension) is the easiest way to start writing C# on any platform.
  3. The dotnet CLI is your gateway to creating, building, running, and publishing .NET applications.
  4. Project structure is straightforward: Program.cs contains your code, .csproj contains project settings, and bin/ and obj/ are build artifacts you generally ignore.
  5. You only need three things to start: the .NET SDK, a code editor, and the dotnet CLI. Everything else is optional.

1. What is the main purpose of the .NET SDK?

  • A) Only to run existing .NET applications
  • B) To provide everything needed for .NET development (runtime, compiler, CLI, and libraries)
  • C) To replace the need for a code editor
  • D) To install Visual Studio automatically
Show answer

✅ Correct: B

Why B is correct: The .NET SDK (Software Development Kit) includes the runtime, compiler, command-line tools, and class libraries needed to build .NET applications.

❌ Why A is incorrect: The runtime alone is enough to run existing applications. The SDK includes additional tools needed for development.

❌ Why C is incorrect: The SDK does not replace a code editor. You still need an editor like VS Code or Visual Studio to write code.

❌ Why D is incorrect: The SDK does not install Visual Studio. They are separate installations.

Reinforcement: The SDK is the complete package for development. It includes everything you need to write, build, and run C# applications.

2. Which command verifies that the .NET SDK is installed correctly?

  • A) dotnet verify
  • B) dotnet --version
  • C) dotnet check
  • D) dotnet --validate
Show answer

✅ Correct: B

Why B is correct: dotnet --version displays the installed .NET SDK version and confirms the SDK is properly installed and accessible.

❌ Why A is incorrect: dotnet verify is not a valid dotnet command.

❌ Why C is incorrect: dotnet check is not a valid dotnet command.

❌ Why D is incorrect: dotnet --validate is not a valid dotnet command.

Reinforcement: After installing the SDK, always run dotnet --version and dotnet --info to verify the installation.

3. You're on macOS and want to start learning C#. Which tool is your best choice for a lightweight, beginner-friendly experience?

  • A) Visual Studio (full IDE)
  • B) Visual Studio Code with the C# extension
  • C) JetBrains Rider
  • D) Notepad and the command line
Show answer

✅ Correct: B

Why B is correct: Visual Studio Code is cross-platform, lightweight, free, and works on macOS. The C# extension provides IntelliSense, debugging, and project management.

❌ Why A is incorrect: Visual Studio is Windows-only (the full IDE is not available on macOS).

❌ Why C is incorrect: Rider is powerful but paid, and it's more complex than needed for a beginner.

❌ Why D is incorrect: Notepad offers no IntelliSense, syntax highlighting, or debugging support, making development much harder.

Reinforcement: For beginners, VS Code with the C# extension is the best choice because it's free, cross-platform, and easy to use.

4. What command creates a new C# console application named "LearningCSharp"?

✅ Correct: A

Why A is correct: dotnet new console -n LearningCSharp creates a new console application template and names it "LearningCSharp."

❌ Why B is incorrect: dotnet create is not a valid dotnet command. The correct command uses new.

❌ Why C is incorrect: dotnet new app is not a valid template name. The correct template is console.

❌ Why D is incorrect: dotnet start is not a valid dotnet command for creating projects.

Reinforcement: Always use dotnet new [template] -n [ProjectName] to create new projects.

5. Which of the following is NOT a file or folder created when you run dotnet new console -n MyApp?

  • B) MyApp.csproj
  • C) appsettings.json
  • D) bin/ folder
Show answer

✅ Correct: C

Why C is correct: appsettings.json is a configuration file typically used in ASP.NET Core web applications, not in a simple console application.

❌ Why A is incorrect: Program.cs is the main entry point and is always created in a console application.

❌ Why B is incorrect: MyApp.csproj is the project file and is always created.

❌ Why D is incorrect: The bin/ folder is created automatically when you build the project.

Reinforcement: A console application template creates only the essential files: Program.cs, .csproj, and the build output folders (bin/ and obj/).
